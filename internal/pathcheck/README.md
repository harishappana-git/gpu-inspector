# Optional path checks

`Run(ctx, Options)` performs no active operation with zero options. A positive `DiskBytes` opts into a disk test; it also requires an explicit existing `Workspace`. A nonempty `URL` opts into exactly one HTTPS object request. `DownloadBytes=0` selects an 8 MiB body budget after endpoint opt-in. The public default disk constant is 16 MiB; `DiskBytes=0` disables disk testing. Both payload caps are 64 MiB. The default combined deadline is 30 seconds, constrained further by the caller's context.

The disk test creates a private tempfile in the explicit workspace, immediately unlinks it, and keeps the owned descriptor until completion. Generated public-seed pattern bytes are written in 64 KiB operations, synced, reread and SHA-256 compared. No existing file contents are opened or modified. Descriptor cleanup also occurs on process death on the supported Linux/macOS path. The caller should run path checks in a killed-on-deadline helper because a filesystem syscall can block below Go's context cancellation. An initial unlink failure aborts before payload writes; the adapter only attempts cleanup while the pathname still identifies its created inode.

Reported rates separate buffered write plus sync from immediate buffered reread; generation/hashing are outside the per-operation timing. The default 16 MiB provides 256 samples per direction. Empirical p95 appears only with at least 100 operations; p99 and production-tail claims are suppressed. There is no direct I/O, cache dropping, cold-cache establishment, burst exhaustion or hardware-media benchmark. F07 verifies only the owned file bytes with this method.

The HTTPS adapter rejects userinfo, queries and fragments, uses certificate verification, disables inherited proxy configuration and decompression, caps response headers, and follows no redirects. It requests a bounded range and reads at most the explicit response-body cap even if the server ignores Range. The byte cap describes payload consumed by the process; DNS, TLS, headers and transport buffering add overhead. No body is written to disk or exported. Evidence contains an endpoint digest, HTTP status/protocol, durations and byte counts; it omits URL paths, hostnames, headers and content. Endpoint selection is the user's explicit object choice; content authenticity and licensing are not independently checked. No full-object completion estimate is produced from a single bounded request.

Tests cover preserved user files, scratch cleanup after cancellation, byte caps, corrupted readback detection, insufficient latency samples, denied URL shapes, HTTP failures, TLS verification, suppressed redirects and environment proxies, and metadata privacy. Network fixtures use only loopback TLS servers; no external service is contacted.
